# Scraps v2 UI — Goal Spec (A×C Hybrid)

> Status: decided 2026-08-30. The mockups in `design/v2/mockups/` are the visual
> goal; this document is the behavioral goal. Where they disagree, this document
> wins (one known deviation is called out in §4). Exploration history lives on
> the design canvas (private): four directions — Compiler / Editorial /
> Workbench / Terminal — were drafted and the chosen form grafts the Workbench
> shell onto the Compiler tone.

## 1. Decision summary

- **Tone**: the existing token system pushed further — Nord roles, hairlines
  only, radius 2/4, no shadows, monospace as the *syntax* signal. Typed
  primitives are rendered as syntax: wiki-links show dim `[[ ]]` brackets,
  tags render as `#[[tag]]` literals.
- **Shell**: a persistent 264px left sidebar (from the Workbench direction)
  holding search, the sort views, and tags.
- **Contexts are not navigation.** `ctx` is a namespace — part of a scrap's
  identity, not a semantic category. It never appears in the sidebar; it shows
  only as a row prefix (`DevOps capabilities/`) and on the scrap page
  breadcrumb. This keeps it visually distinct from tags.
- **Differentiation vs Obsidian Publish / Quartz** (design principles, keep
  these true):
  - no file tree in the sidebar — views + tags only
  - no graph visualization pane
  - brackets visible on typed references (`[[ ]]`, `#[[ ]]`) — Obsidian hides
    them in preview
  - Nord + mono metadata + build-log styled stats (`built 1.4s`) — the page
    reads as *compiler output*, not a note app's publish surface
  - default `os_setting` color scheme: the light theme is a nord6 paper
    ground, further from the dark-app first impression

## 2. Functional changes (v2, breaking)

1. **README stays on the home — the shell absorbs it.** v1's problem was that
   the home's entire structure depended on README content. v2 fixes the
   structure instead of dropping the feature: the sidebar (nav / search /
   tags) and the view header + stats line are always present, and an optional
   README block renders in the content column above the scrap list. No
   config — the presence of README.md is the switch. The docs site's own home
   relies on this. `mockups/home.html` shows the README-absent case.
2. **`sort_key` config is removed.** Every sort view is always generated:

   | View | Route | Order | Pagination |
   |---|---|---|---|
   | updated (Home) | `/` | committed date desc | as today |
   | backlinks | `/backlinks/` | linked count desc | same mechanism |
   | title index | `/titles/` | grouped by initial | single page |
   | all scraps | `/scraps/` | existing dense index | as today |

   Title-index grouping: normalize (NFKC, katakana→hiragana, fold
   dakuten/handakuten so デ→て), then group into kana rows あ か さ た な は
   ま や ら わ; Latin initials into A–Z; CJK-ideograph initials into a 漢字
   group (codepoint order — no dictionary readings, per the lean-core
   principle); digits and anything else into `#`. A group with no scraps is
   not rendered at all — neither as a section nor in the jump bar.
3. **Scrap page** gains: its own tags (as `#[[tag]]` literals above the
   title), and two labeled sections after the content — `backlinks · N` and
   `links · N` (resolved outbound wiki-links). The trailing unlabeled
   backlinks list is gone.
4. **Autolink cards are static.** The runtime OGP fetch (corsproxy.io) is
   removed. The card is rendered at build time from the URL alone: host as the
   prominent line, full URL in mono below. *(Deviation from the mockup: the
   mockup shows a fetched page title on the card; v2.0 does not fetch — no
   network at build, no client fetch. A future plugin may enrich cards.)*
5. **Search stays** (fuse.js, title-only) but moves into the sidebar; the
   results dropdown must be laid out with normal flow/positioning — no inline
   per-item pixel offsets.

## 3. Layout (see mockups)

- `mockups/home.html` — sidebar + "Recently updated" list view. Rows: title
  (accent, 500), optional mono ctx prefix, one-line muted summary, right
  column with date and `n refs · m backlinks` (mono).
- `mockups/scrap.html` — sidebar persists; article column 760px; tag line,
  title (34px), `committed …` (mono), hairline, prose (16/1.7), static link
  card, then `backlinks · N` / `links · N` sections as 2-column hairline
  grids. Status bar shows `scraps / <title>` breadcrumb.
- `mockups/title-index.html` — jump bar (kana | A–Z | #) with dim empty
  groups, then per-group sections with 3-column hairline grids of title +
  backlink count.
- Status bar: hairline top, mono, left contextual info, right
  `Generated by Scraps`.
- **Responsive** (<768px): the sidebar collapses to a simple top header
  (wiki title + links to the views); no horizontal scroll anywhere. A fancier
  drawer is out of scope for v2.0.

## 4. Tokens

- Existing six color roles stay. Add **`color.accent-wash`** — the active/
  selection background behind accent text (sidebar active view, jump-bar
  active group). Dark ≈ `rgba(136,192,208,.14)` over nord0, light ≈
  `rgba(71,105,143,.12)` over nord6; if the token pipeline cannot express
  alpha, use the pre-composited solids (dark `#3d4a55`-ish, light
  `#dde4ed`-ish). Accent text on the wash must keep AA (the
  `tokens:check-contrast` gate applies).
- Bracket dimming for `[[ ]]` / `#[[ ]]` uses an existing low-emphasis color
  (rule or a nord step) — do not invent a new role unless contrast gates force
  it.
- Typography and spacing scales unchanged (Rubik + Noto Sans JP, mono for
  metadata/syntax, 4px scale, radius 2/4).

## 5. Out of scope (v2.0)

Graph visualization; contexts navigation; JS drawer; fetched OGP titles;
kanji-reading-based indexing (tokenizer = plugin candidate); RSS per view.

## 6. Verification per iteration

- `mise run cargo:quality` and `mise run tokens:check` stay green.
- Build `docs/` with the binary from this checkout, serve it (`scraps serve`),
  and compare each page against the mockups.
- Playwright e2e (`mise run e2e:test`) updated alongside behavior changes.
- Build-time budget: ≤ 3s target, 4s hard CI limit (boykush/wiki).
- `design/storybook/` stories mirror the final Tera markup (hand-synced
  duplicates — change one, change the other).
